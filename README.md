# astock-watch · A 股个股分析与实时盯盘

一个**零依赖**（只用 Python 标准库）的 A 股技术分析与盯盘工具：日线结构 + 资金流 + 量能形态，
输出「评分 → 结论 → 具体价位 → 操作指令」，盘中按规则实时告警。

> 数据源：东方财富公开行情接口（免费、无需 token）。**不含自动下单**，只做分析与提醒。

---

## 0. 安装

```bash
git clone https://github.com/<your-name>/astock-watch.git
cd astock-watch
cp config.example.json config.json     # Windows: copy config.example.json config.json
```

- **不需要 pip install**：Python ≥ 3.7 与 Node（仅 K 线自检用）即可，全部逻辑只用标准库；
- 打开 `config.json`，把你的模型网关填进 `ai` 段（`provider` / `base_url` / `model` / `api_key`），
  或直接启动 Web 控制台在「设置」页填；
- 体检：`python main.py ai --doctor`；
- 启动：`python main.py serve`（或双击 `启动Web服务.bat`）→ <http://127.0.0.1:8770>

> `config.json` 含密钥，已被 `.gitignore` 排除，永远不会提交到仓库。

## 3. 决策引擎怎么算的

### 3.1 五维评分（满分 100）

| 维度 | 权重 | 看什么 |
|---|---|---|
| 趋势 | 30 | 股价站上几条均线（MA5/10/20/60）、均线是否多头排列 |
| 位置 | 20 | 距 60 日高点回撤、距 MA20 偏离、区间分位、**距支撑带几个 ATR** |
| 动能 | 20 | MACD 柱方向与拐头、是否金叉、RSI6、KDJ |
| 量能 | 15 | 今日量 / 5 日均量（放量阳 vs 缩量阳含义不同）、量比、换手 |
| 资金 | 15 | 主力（超大单+大单）今日 / 3 日 / 5 日 / 10 日净额及其收敛速度 |

### 3.2 双维度判定（关键设计）

抄底和追势是两套逻辑，混在一起会得出错误结论（底部永远「趋势很差」）。所以拆成：

- **右侧分** =（趋势 + 动能）→ 回答「**趋势转强了吗，能不能加仓**」
- **左侧分** =（位置 + 量能 + 资金）→ 回答「**跌够了没，支撑值不值得守**」

决策矩阵：

| 右侧分 | 左侧分 | 结论 | 动作 |
|---|---|---|---|
| ≥60 | ≥50 | 右侧成立 | **加仓 / 建仓** |
| ≥60 | <50 | 趋势强但位置高 | 可参与，勿追高 |
| 40–60 | ≥55 | 趋势回暖且位置低 | 持有，可小幅加仓 |
| 40–60 | <55 | 中性 | 持有观察 |
| 20–40 | ≥50 | 支撑区但趋势没确认 | **只留试探仓，禁止加仓，严格止损** |
| 20–40 | <50 | 双弱 | 反弹减仓 |
| <20 | ≥50 | 深度超跌 | 试探仓 + 铁止损，禁止补仓摊薄 |
| <20 | <50 | 双弱 | 离场观望 |

另附**右侧确认清单**（4 项打勾）：放量阳线 / 收复 MA10 / MACD 金叉 / 主力 3 日转正。
清单满足 ≥2 项，才是「可以加仓」的客观证据。

### 3.3 价位怎么来的

`config.json → symbols → <代码>` 里的人工价位**优先**（我这几天给你的结论就写在这里）；
没配置时自动推导：近 120 日枢轴低点**聚类**得支撑带（被触碰 ≥2 次才算有效）、
MA10/MA20/MA60 与枢轴高点得阻力、止损 = min(支撑×0.99, 现价−1.2×ATR)。

### 3.4 持有模式（短线 / 中线 / 长线）—— 到期由代码强制了结

「持有多久」是纪律，不能靠模型每天心情，所以放在**代码层强制**（`astock/holdmode.py`）。
网页「设置」页可切换，**即时生效、不用重启**；模式记在 `data/ai/hold_mode.json`，
`config.json → ai.hold_mode` 只做兜底。

| 模式 | 单票最长持有 | 止盈参考 | 说明 |
|---|---|---|---|
| **短线（默认）** | **3 个交易日** | 3%~6% | 小资金快买快卖，不参与横盘磨 |
| 中线 | 10 个交易日 | 8%~15% | 波段，允许一次正常回踩 |
| 长线 | 20 个交易日 | 15%~30% | 趋势跟随（回放里扣费后超额最高，但占资金最久） |

口径：**持有交易日数含买入日**（买入当天 = 1 天）。上限 3 天时，第 2 天收盘就生成
「次日开盘卖出」计划单，第 3 个交易日了结 —— AI 输出 HOLD 也会被代码覆盖。
盘中若已超期（持有 ≥ 上限），代码直接补一条 SELL。

### 3.5 计划单分三类：买入 / 卖出 / 待观察

收盘后（15:15）的决策会落成三样东西，邮件与网页都按这三块展示：

1. **买入计划单**：`for_date` = 下一交易日，开盘按规则成交（高开 >1.5% 不追、跳空破止损取消）；
2. **卖出计划单**：止损/止盈/**时间止损**（持有到期）都会在这里，先处理持仓再谈开新仓；
3. **明日待观察（看好名单）**：最多 5 只，带「关注理由 + 触发条件 + 优先级」，回答
   「明天哪些票看好、什么条件下动手」——即使当天不买，也会列出，不会因为空仓就什么都不说。

 文件位置：`data/ai/plans/pending_plans.json`（买卖）、`data/ai/plans/tomorrow_watch.json`（关注）、
过期旧单自动归档到 `data/ai/plans/history/`（不会再有「明日计划还是昨天那张」的情况）。

**卖出腾出的钱当天就能买**：收盘计划阶段会先按「卖单成交后」的账户算额度（现金、仓位、组合风险），
所以「今天满仓」不会成为明天不出买入计划的理由；执行时也是先卖后买，同一份资金不重复计算。
每日交易笔数上限默认**不限制**（`rails.max_trades_per_day = 0`；设成正数则生效，
超出的买入计划会在落盘前就被砍掉，不会出现执行不了的条目）。
到期卖出**不依赖模型**：模型调用失败时，代码仍会按纪律把卖出计划单写出来。

### 3.6 Token / 上下文策略：不设人为上限

按「用足模型能力」的原则，输出额度与提示词都不再人为压缩：

- `max_tokens*` 全部取模型输出上限（`cn:deepseek-v4.1-flash` = **393,216**，上下文 1M，已实测网关接受），
  `max_tokens_ceiling` 控制截断时的自动升额天花板，`timeout_sec` 相应放大到 900s；
- 提示词不再截断：策略手册全文、先验全文、K 线 `bars_in_prompt=60` 根、板块前 20、
  日记/持仓全量进上下文；
- 代价是每次调用的 token 与 credit 明显上升（实测：决策阶段 prompt 从 ~1.5 万 → **3.2 万**，
  completion ~8.5k，单次约 3.7 credit）。要省就把 `max_tokens_decide` 等调小即可，无需改代码。

## 4. 盯盘告警（9 类）

| # | 类型 | 触发条件 | 级别 |
|---|---|---|---|
| 1 | **止损** | 现价 ≤ 止损价 | 操作 |
| 2 | 回踩支撑 / **跌破支撑** | 距支撑 ≤0.6%；或有效跌破（逐级报下一道支撑） | 提示 / 注意 |
| 3 | 突破阻力 | 现价 ≥ 阻力位（逐级） | 操作 |
| 4 | **加仓触发价** | 现价 ≥ `add_trigger` | 操作 |
| 5 | 目标位 | 现价 ≥ 各目标位（提示分批止盈） | 操作 |
| 6 | 急涨急跌 | 5 分钟内波动 ≥1.5%（可配窗口） | 注意 |
| 7 | 单日涨跌幅 | 当日 |涨跌| ≥5% | 注意 |
| 8 | 放量 | 今日量 ≥ 5 日均量 ×2.5 倍 | 注意 |
| 9 | 均线收复/失守 | 实时价上穿/下破 MA5、MA10、MA20（用实时价重算均线） | 操作/提示 |
| 10 | 评分跳变 | 评分变动 ≥8 分（评级可能换挡） | 提示 |

- 同一条件 **冷却 15 分钟**（`alerts.cooldown_sec`），避免刷屏；
- 每条告警同时写入 `data/logs/alerts_YYYY-MM-DD.log`，可事后复盘「当时到底发生了什么」；
- 「操作」级告警触发 Windows 蜂鸣三连音。

## 7. 示例：一次真实的输出（2026-11-02 收盘，盈新发展 000620）

> 下面是这套系统在真实行情下对一只票给出的结论，可用于理解它「怎么说话」。

```
【弱势筑底】 综合 31｜深度超跌但趋势极弱（右侧 11 / 左侧 54）
        动作指令：左侧支撑区：仅保留试探仓，禁止加仓，严格止损
        综合强度 31/100  ██████░░░░░░░░░░░░░░
        分项：趋势 0/30 | 位置 14/20 | 动能 5/20 | 量能 9/15 | 资金 3/15
【技术面】 均线 MA5 2.68 / MA10 2.75 / MA20 2.84 / MA60 3.02｜MACD 未金叉｜RSI6 30.9
          形态 下影 0.05 > 实体 0.02（长下影）｜周线空头
【资金面】 主力今日 -1319 万（前一日 -5770 万，流出收窄）｜3 日 -9659 万
【关键价位】 支撑 2.56 / 2.53 / 2.41｜阻力 2.65 / 2.74 / 2.83
          止损 2.53｜目标 2.83 → 3.02 → 3.20
【右侧确认清单】 0/4 项满足（放量阳线 / 收复 MA10 / MACD 金叉 / 主力 3 日转正）
```

读法：**右侧分低 = 趋势没确认，不许加仓；左侧分高 = 位置到了，值得守**。
所以结论是「保留试探仓 + 严格止损」，而不是「抄底梭哈」——这就是双维度评分存在的意义。

## 8. 已知限制（务必知悉）

1. **免费接口**：无 Level-2 逐笔、无盘口十档；盘中数据约 3–15 秒延迟；极端行情下接口可能限频（已内置重试）。
2. **日线级信号**：评分以日 K 为主，盘中告警是「价格 vs 关键位」的实时比对，不是分钟级形态识别。
3. **不含交易**：不做任何委托下单，落单请自行在券商 App 操作并核对价格。
4. **评分是相对刻度**：不同股票间横向量化比较意义有限，用于**同一只票的时间序列对比**最有效。
5. 一切输出为技术分析参考，**不构成投资建议**。

## 11. 数据安全与备份（账户与记忆永不丢失）

你的**账户与成交**（`data/ai/paper_state.json`）、**AI 记忆**（`playbook.md` 手册、`journal/` 日记、
`lessons.json` 教训、`watchlist.json` 观察池、`plans/` 计划单）都在 `data/` 下，**永远不会被自动清空**。

三种保护机制：

| 机制 | 说明 |
|---|---|
| **自动备份** | 服务启动时、每轮 AI 决策/复盘后、重置模拟盘之前，自动打包 `data/` → `backups/astock-data-<时间>-<原因>.zip`（保留最近 30 份） |
| **手动备份 / 恢复** | `python main.py backup --list` 体检；`python main.py backup` 立即备份；`python main.py backup --restore <zip>` 回滚（回滚前会自动先备份当前数据） |
| **Web 一键操作** | 设置页「数据备份」卡片：立即备份、查看列表、点条目回滚 |

```bash
python main.py backup --list          # 数据体检 + 已有备份列表
python main.py backup --reason 里程碑   # 打一个带备注的备份
python main.py backup --restore backups/astock-data-20261103-104257-server-start.zip
```

> `backups/` 与 `data/` 都在 `.gitignore` 里：**备份含账户信息，不会进入 git 仓库**。

## 12. 扩展：大盘温度 / 板块强度 / 报告图表 / 可选基本面

### 12.1 大盘温度闸门（弱势自动收紧）

`astock/market.py` 用四个客观维度合成 0~100 的「大盘温度」：指数涨跌、涨跌家数广度、
涨停/跌停家数、上证相对 MA5/MA20 的趋势。温度直接翻译成**代码级**收紧策略：

| 温度 | 等级 | 代码行为 |
|---|---|---|
| < 30 | 冰点 | **禁止开新仓**（只管理现有持仓） |
| 30~44 | 偏冷 | 允许开仓，但单股上限压到 25% |
| 45~59 | 中性 | 常规风控（35%） |
| ≥ 60 | 偏热/过热 | 按原上限，但提示追高风险 |

温度与「行业板块涨幅前列」「个股所属板块」都会进入 AI 的决策上下文，但**收紧动作由代码执行，
不看模型脸色**。网页仪表盘有实时温度卡片，接口：`GET /api/market`。

### 12.2 报告里的 K 线图（纯 SVG）

`astock/chart_svg.py` 用**手绘 SVG** 生成 K 线图（蜡烛 + 成交量 + 四条均线 + AI 买卖点标记），
零依赖、可直接在浏览器/GitHub 预览：

```bash
python main.py daily                  # 生成 data/reports/daily-*.md + *.html（内嵌 SVG）+ <code>_kline.svg
python main.py daily --no-svg         # 只要文字报告
```

### 12.3 可选基本面：财报 / 股东 / 龙虎榜

`astock/altdata.py` 是**可选**适配层，装了就自动启用，没装系统照常跑（AI 只是少一份参考资料）：

```bash
pip install akshare       # 免费、免 token，推荐
pip install tushare       # 需在 config.json → ai.use_altdata 与 ai.tushare_token 配置
```

取到的数据带 6 小时缓存（`data/altdata/<code>.json`），进提示词前会压成 3~6 行摘要，
不会把整张财报塞给模型。安装状态见网页「设置 → 扩展数据源」，接口：`GET /api/altstatus`。

### 12.4 板块强度过滤（弱势板块直接不看）

config.json → ai.sector_filter 控制（已默认开启）：

| 参数 | 默认 | 含义 |
|---|---|---|
| enabled | true | 是否启用 |
| weak_pct | -1.5 | 个股**最强所属板块**当日涨幅低于该值 → 视为弱势板块 |
| drop_weak | true | 选股候选池直接剔除；观察池剔除；**买入指令在代码层被拒** |
| min_candidates | 5 | 过滤后至少保留的候选数（防止池子被清空） |

提示词里也会带上过滤规则，但真正的拦截在 i_agent._execute 与 screener.screen 里执行。

## 13. 实盘成交流水与真实绩效

在「我的持仓」页记录自己的真实买卖（买入/卖出/加仓都行），系统自动算出：

| 指标 | 口径 |
|---|---|
| 摊薄成本 | 加权平均法（含手续费计入成本） |
| 已实现盈亏 | 每次卖出按当时的均价结算 |
| 胜率 | 盈利平仓次数 ÷ 总平仓次数 |
| 盈亏比 | 总盈利 ÷ 总亏损；同时给出平均盈/平均亏 |
| 推导持仓 | 由流水回放得到当前持股与摊薄成本，可一键覆盖「我的持仓」表 |

安全阀：流水推导不出持仓时**拒绝覆盖**持仓表（避免流水没记全就把手工数据清空），
确认清空需显式传 `force`。

邮件里也会带上这份实盘绩效小卡片；**每日报告会以 HTML 文件作为附件**一起发出。
